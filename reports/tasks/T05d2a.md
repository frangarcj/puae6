# T05d2a — lectura zfile sobre assets registrados

El zfile.cpp materializado selecciona un backend portable mediante el parche
0005. Conserva los headers y el layout zfile de 6030; conecta apertura, lectura,
seek, tamaño, cierre, nombres y errores al almacen de blobs de T05d1. No compila
filesystem, archives ni callbacks host. La implementacion original permanece
sin cambios para builds que no definan P6_PORTABLE.

Decision: zfile.cpp mezcla primitivas de memoria con filesystem, plugins y
archives. Se selecciona una implementacion portable acotada, en vez de portar
todo ese conjunto. No se reutilizan los cuerpos originales de las primitivas:
el coste es mantener equivalencia de sus contratos y revisar callers al actualizar
upstream. Los auxiliares aun pendientes quedan sin definir, no como stubs exitosos.

ZFD_NORMAL y ZFD_DISKHISTORY valen cero solo en este perfil: disk.cpp intenta
r+b con ambos flags y despues rb. La escritura falla con EROFS; la lectura usa
el identificador registrado. Las solicitudes explicitas de archives/unpack y
otros formatos excluidos fallan con ENOTSUP. El tipo registrado declara bytes
raw; no prueba geometria, contenido ni content ID de ROM/ADF (T12/MED01).

La API legacy fread no recibe capacidad: el caller debe aportar un destino
valido para width*count. Se comprueban multiplicacion y EOF, pero no se puede
detectar un buffer caller de tamaño insuficiente. fread32 comprueba el numero
real de elementos retornables antes de convertir a signed32. Los errores quedan
registrados; EOF por si solo no es error. Seek fuera de rango conserva el clamp
de la primitiva y devuelve error. exit cierra cursores sin borrar los assets.

Pruebas sobre zfile.cpp real materializado, con ASan/UBSan: lectura por elementos,
EOF parcial, canarios, overflow, seek extremo, errores, cursores independientes,
rechazo individual de flags excluidos, agotamiento y reutilizacion de los 64
slots, cierre repetido y handles invalidados. Inyeccion de calloc fallido confirma
que se libera el handle del blob antes de devolver ENOMEM. Depfiles verifican los
headers reales y nm solo permite memoria/alloc/errno libc y el backend de blobs.
Revision Luna sin defectos concretos en la ruta comprobada.
