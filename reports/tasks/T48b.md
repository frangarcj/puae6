## Implementado

- `tests/build_support.py` identifica inputs por contenido (incluido trabajo sin
  commit), configuracion, CMakeCache, recibo de codegen y hashes de artefactos.
  Reutiliza la preparacion dentro de un proceso, no una instancia emulada.
- Configuraciones Debug, sanitizers y trace se separan. Un target nuevo no repite
  configure; un fallo no queda cacheado. Un binario alterado se rechaza.
- Un lock de threads y procesos protege las preparaciones nativas que usan el
  helper, porque comparten upstream y generados. No protege CMake manual ajeno.
- `build_probe` y `configure_trace_tree` usan ese helper. Los llamadores actuales
  incluyen el core libretro compartido: se resuelve su archivo .dylib/.so, no se
  supone que el nombre de target sea un ejecutable sin extension.
- El runner host prepara lifecycle, memory y profile antes de lanzar los workers
  seleccionados. Con sanitizers prepara tambien sus variantes correspondientes.
  Cada worker comprueba un recibo temporal y no puede arrancar otro build.
