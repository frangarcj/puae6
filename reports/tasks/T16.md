# T16 BLOCKED: falta un frontend libretro real; el adaptador esta hecho (T16a)

La ficha pide ejecutar el core con un frontend real y dice que un harness solo no sustituye ese humo. En esta maquina no hay RetroArch ni otro frontend libretro
(`which retroarch`, /Applications, Homebrew: nada) y no se instala software global sin autorizacion del usuario, asi que esa parte queda sin hacer. El resto se hizo como T16a
y esta commiteado.

## Que prueba T16a (con el frontend de referencia tests/libretro-host, que carga el core con dlopen)

`python3 -m unittest discover -s tests/libretro-host` (13 tests):

- LR01: cada `retro_run` hace un poll de entrada y muestra exactamente un cuadro; la informacion de A/V es la que entrega el core; el pixel format se negocia (XRGB8888 es el
  unico, y si el frontend lo rechaza el load falla con mensaje y sin fallback); un firmware que el bridge rechaza falla el load y deja el core usable; una llamada libretro
  desde dentro de un callback se ignora sin avanzar ninguna unidad; `serialize_size` es 0 y no cambia.
- STEP01: N `retro_run` son N unidades del adaptador headless con los mismos ticks, el mismo hash de imagen y los mismos frames de audio por unidad (boot y long_frame, que
  tiene unidades sin cuadro nuevo).
- AV01/AV02: el cuadro activo recortado con pitch >= 4*ancho; sin cuadro nuevo se repite el anterior (NULL si el frontend puede duplicar, una copia si no); el audio que el
  frontend toma en trozos de 100 o de 1 frame, o que retiene durante cuatro runs, llega entero y en el mismo orden (mismo hash del flujo PCM); un frontend que nunca lo toma no
  hace crecer el core sin limite (cola de 16384 frames, aviso al descartar).
- LIFE01: 6 ciclos load/run/unload con el mismo resultado; la entrada del frontend llega al bridge como fija el contrato (B/A/X -> botones 1/2/3, cruceta, raton solo en el
  puerto 0).
- Frontera: la biblioteca exporta exactamente los 25 `retro_*` y enlaza solo libSystem y libc++ (sin Framework).

## Lo que T16a NO hace (llega con T17/T18)

Opciones del core (PAL/NTSC, semilla, epoca), carga de discos y del Kickstart desde el directorio de sistema, teclado, regiones de memoria y estados (`serialize_size` 0).
El contenido de `retro_load_game` es el firmware. NTSC no se puede elegir desde libretro todavia, asi que AV01 por libretro solo cubre PAL.

## Para desbloquear

Instalar un frontend real (p. ej. `brew install --cask retroarch`, decision del usuario) y ejecutar `build/link-audit/puae6_libretro.dylib` con un micro-ROM (`tests/fixtures/
microrom/boot.s` con `tests/fixtures/microrom/build_rom.py`) con video/audio nulos durante unos cientos de frames; comprobar carga, descarga, que el frontend no se queja de la
geometria ni del audio y que el log (`--verbose`) muestra una unidad por frame. T17 y T19 dependen de esta ficha, asi que tambien quedan sin empezar.
