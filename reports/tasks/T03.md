# T03 — generadores HOST y materializacion exacta

Comandos implementados:

- `python3 tools/materialize_upstream.py`: verifica pristine y materializa
  `build/upstream`; no sobrescribe un destino distinto.
- `python3 tools/generate_cpu.py --check`: construye y ejecuta dos veces los
  cinco generadores en directorios limpios; compara los hashes de sus 39 salidas.
- `python3 tools/generate_cpu.py`: publica `build/generated`, con receta,
  compiladores, hashes de ejecutables HOST, inputs transitivos via depfiles y
  outputs en `codegen-receipt.json`. `--cc`/`--cxx` seleccionan compiladores HOST.
- `cmake/HostTools.cmake`: `p6_add_host_codegen(nombre)` crea el target; exporta
  listas explicitas de fuentes y orden de includes. El consumidor debe declarar
  `add_dependencies(su_target nombre)`. Configure no ejecuta generadores.

Validacion local: Apple Clang 21, macOS ARM64. GEN01: 39 salidas identicas en dos
builds limpios. Target CMake compilado y ejecutado con CMAKE_CXX_COMPILER apuntando
intencionadamente a una ruta inexistente: usa exclusivamente los compiladores
HOST. SRC01: verificados offline los 8.427 archivos de las siete fuentes.

## Decisiones que importan al continuar

`build68k` se compila solo, recibe table68k por stdin y genera cpudefs antes de
compilar gencpu. No necesita bootstrap con cpudefs pristine, missing.cpp ni
unicode.cpp. Las cabeceras de tools/codegen_host solo sirven a estas herramientas;
no implementan contratos del motor. frequent.68k esta explicitamente ausente.

`gengenblitter.cpp` es C, pese al sufijo: usa enumeradores con alcance de C.
Un parche elimina includes de configuracion del motor que no usa; se compila
con `-x c -std=c11`. No se modifica su algoritmo. genlinetoscr se ejecuta dos
niveles por debajo del directorio generated para confinar sus rutas `../../`.

37 productos coinciden byte a byte con el snapshot. blitops.cpp y blit.h difieren
en las expresiones de los minterms 0x3e, 0x5e y 0x76. La prueba C compilada valida
los 256 minterms por sus 8 combinaciones de entrada, para ambas versiones. Al
ser expresiones exclusivamente bitwise, esto cubre cada bit de los operandos de
32 bits. Se acepta la regeneracion con esa prueba; no se cambia ningun golden.
El origen historico de las formas distintas del snapshot no esta demostrado.

Los includes de salidas generadas en drawing/newcpu/blitter pasan a usar el
include path para evitar que las copias pristine del mismo directorio tengan
prioridad. Solo se seleccionan cinco unidades generadas para el perfil A500;
producir otras familias CPU no implica habilitarlas ni compilarlas.

cpustbl regenerado reproduce el guard upstream: op_smalltbl_14 queda fuera del
endif CPUEMU_13. T06 debe resolver las referencias del dispatch con una prueba
de enlace del perfil; no se edita el output ni se poda el generador aqui.

La materializacion comprueba hashes previos/posteriores y el inventario completo,
rechaza offsets y publica atomica. git apply necesita aislar el descubrimiento
del repositorio padre: un fixture bajo build cubre esa regresion. Cambiar la cola
o receta con outputs existentes distintos exige conservarlos aparte antes de
regenerar; el runner no los borra ni repara silenciosamente.

Esto valida generacion de fuentes en este HOST. No demuestra reproducibilidad
binaria/entre hosts, compilacion del core ni ejecucion dentro de Waterbox.
Los depfiles -MMD registran headers del proyecto, no todos los headers del SDK;
no usar esta identidad para compartir caches entre SDK/hosts distintos.
