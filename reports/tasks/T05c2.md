# T05c2 — diagnosticos acotados y estado causal

Implementados write_log/write_logx/write_dlog, console_out/console_out_f,
gui_message, notify_user/notify_user_parms, logging_init y lectura batch C.
La cola contiene 32 registros de 256 bytes de texto, en almacenamiento ordinario
del guest, sin punteros prestados. Desborde descarta mensajes nuevos y cuenta
perdidas con saturacion; truncamiento y formato invalido se indican en flags.
La salida es una secuencia de bytes: una secuencia UTF-8 cortada se presenta con
replacement. vsnprintf pertenece a la libc del target; no se afirma que sus
internos nunca asignen memoria. errno se conserva durante el formato.

gui_message_multibutton devuelve -1 y registra UNSUPPORTED: no confirma acciones.
notify_user conserva el codigo upstream. notify_user_parms soporta la unica forma
llamada en las unidades seleccionadas (NUMSG_ROMNEED, con el string en la elipsis);
otros codigos con parametros quedan marcados UNSUPPORTED sin consumir varargs.

gui_data usa el header upstream real. CIA escribe powerled/brillo antes de
gui_led, y audio.cpp usa powerled para Paula. gui_led mantiene solo bits de
presentacion; un valor negativo refresca sin cambiar el bit, como indicator_leds
upstream. Ni overflow, drenaje ni logging_init alteran el estado causal. gui_fps
actualiza exclusivamente sus campos de presentacion.

Validacion: 105 tests de unittest discovery pasan; probe con ASan/UBSan comprueba
FIFO, vuelta del anillo, overflow, lectura parcial, canario, copia de strings,
limites exactos, errores, errno y preservacion de gui_data. Header C11 compila;
objeto sin sanitizadores solo depende de formato libc, copia/puesta a cero,
errno y stack protector. HOST01 inventario y HARNESS01 T04 pasan.
Revision Luna detecto el caso de LED negativo: corregido y cubierto por test.

La lectura al final de frame es contrato para el futuro bridge, aun no conectado.
No se prueba aqui hash A/V del motor, replay, ni snapshot Waterbox. El error de
carga no se deduce del log: T06/T13 deben conservar la propagacion tipada.
T05c3 conserva los servicios observacionales pendientes (nombres/cambio de discos,
flicker, indicadores de gameport) y la clasificacion de otras APIs legacy al
enlazar. T05c permanece pendiente hasta cerrar esa superficie; no se crearon
stubs exitosos para console/FS/UI interactiva.
