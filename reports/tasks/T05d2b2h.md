# T05d2b2h — datos, CRC, texto y cierre de primitivas I/O

getdata devuelve una copia propia, con offset/longitud comprobados, tamaño
maximo INT_MAX y outlen=0 en error. Una longitud negativa conserva la convencion
upstream de tamaño total, no tamaño restante: con offset no cero se rechaza si
excede el archivo. Cero bytes devuelve una asignacion liberable. Reserva fallida
no mueve cursores; lectura corta no devuelve una copia parcialmente inicializada.
Se restaura tanto el cursor del archivo como el del root si es una vista.

crc32 usa get_crc32 de 6030: RAM directa y copia comprobada para assets/vistas,
sin cambiar cursores. El retorno cero puede ser un CRC valido (por ejemplo vacio);
el error se distingue con ferror. Esta API no sustituye content ID SHA-256 ni
validacion de geometria/firmware. La propagacion de estos errores al loader real
sigue siendo obligatoria en T06/T12/T13.

Texto usa bytes UTF-8 sin conversion dependiente de locale. fgetsa devuelve el
buffer base, incluye newline y conserva NUL embebido. fgets sigue la rama RAM
upstream: consume NUL como terminador, NUL inicial devuelve NULL, y el retorno
exitoso apunta justo despues del NUL final. Sus callers cfgfile solo usan ese
retorno como booleano. Capacidad uno devuelve cadena vacia sin consumir; capacidad
no positiva/null buffer falla. Una capacidad puede cortar una secuencia UTF-8:
son lecturas por bytes, la validacion de config completa corresponde al importador.
EOF inicial devuelve NULL, EOF tras bytes entrega la ultima linea. Un fallo real
de lectura no se convierte en una linea exitosa; el prefijo ya escrito queda
terminado en NUL. La capacidad uno normaliza todos los backends a la regla RAM
de upstream, incluso en EOF; no hereda las variaciones de fgets del host.
putc conserva retorno 1/-1,
fputs retorna elementos escritos y no permite escribir assets. getfilename
extrae el basename de etiquetas RAM sin abrir ninguna ruta.

El test CRC compila sin modificar el prefijo de funciones CRC del crc32.cpp
materializado. Se contrasta con el vector conocido 123456789 (CBF43926), vacio y
las tres representaciones. No compila/prueba SHA ni get_sha1_txt: su _stprintf y
portabilidad deben resolverse en la integracion T06. No se ha introducido un
segundo algoritmo CRC ni un stub para suplirlo.

El inventario vfs en host-surface registra implementaciones y callers seleccionados;
un test exige que no aparezcan huecos nuevos. Permanecen sin definir gunzip
(fallback AROS), zopen (swapper host) y zcompress/zuncompress (estados heredados).
T06 debe excluir sus ramas reales. La auditoria es lexica e incluye ramas
inactivas; no certifica includes/macros/preprocesado ni enlace completo.

## Puerta conjunta T05d

Los probes blob/zfile comprueban permisos rb/r+b, IDs sin fallback, flags excluidos,
EOF, overflow, cursores independientes, ownership de buffers, temporales RAM,
vistas y duplicados, cierre, asignacion fallida y ausencia de simbolos host I/O.
ASan/UBSan y contabilidad de asignaciones ejercitan tambien errores parciales.
T05d1/T05d2a/T05d2b1/T05d2b2v conservan sus decisiones y limites en sus informes.
Esto satisface la puerta de primitivas I/O de T05d2b2/T05d2b/T05d2/T05d. No
convierte los checks de inventario/contrato en emulacion: MED01, enlace del motor,
parsers y su manejo de fallos, serializacion nativa y restore Waterbox siguen
pendientes en sus tareas respectivas.
